# Correction record (Opus, #1778), after the independent reviews

The **first pass is preserved unchanged** at `/private/tmp/tkr-1778-opus-first-pass.tar.gz` (parent-made snapshot). This page records what the four independent reviews (verification, edge, adversarial, structure) found in **my** tools and report. It records what I changed and which experiments I re-ran. Each check is executable: [`correction-checks.mjs`](../../../../tools/research/native-data-notations/opus/correction-checks.mjs) writes `results/correction-checks.json`. Where this page and the README disagree, this page and the re-run `results/` files take precedence over first-pass prose.

| Issue | Defect in the first pass (mine, not a notation limitation) | Correction | Proof |
|---|---|---|---|
| #1780 | The merge oracle for "both add" only checked that the added IDs and the count were present, so a merge that corrupted existing order or references passed. | `classify()` now requires the **whole merged document** to equal one of the two permitted orders exactly. | Reviewer's corruption case is now `FAIL…`; a correct merge is `pass-clean-both-kept`. All 19 scenarios re-run. |
| #1782 | The TOML null marker `{"$null"=true}` collided with real data of that shape, which decoded as null. | Injective mapping: null ↔ `{"$null"=true}`, and every authored key starting with `$` is escaped by doubling the `$`. | Nested real `{"$null":true}`, a `$$x` key and real nulls all round-trip in `toml` and `toml-rows`. Whole cohort re-round-tripped. |
| #1783 | JSON "preserve no-op" returned the untouched input without parsing, so invalid text passed. | The JSON edit path parses the input strictly before editing and the output after. | Invalid input is rejected; a valid no-op is byte-identical. No-op experiments re-run. |
| #1784 | Host parity compared hashes only; an accept-everything schema still "passed". | Every step now makes positive and negative semantic assertions before parity is compared. | Negative control (`schema: true`) fails `rejectsInvalid` and `errorAtExpectedPath`. Node 26.13.0 and Chrome for Testing 150 headless agree on every check and hash. Every library passes except **`edn-data` 1.2.2, which fails `rejectsMalformed` in both hosts** (library defect). |
| #1785 | F1 mixed a whole-project byte count (13.5 MB, 708 documents) with one tile document's line count (23,221). | README F1 rewritten with separate scopes (below). | `results/roundtrip-corpus.json` (project scope) and `results/experiments.json` → `tiles` (document scope). |
| #1786 | Schema lacked `x-ref` on actor combat stances, `progression.onLevelUp` and other projected paths, so rename and checks skipped them. | Added for combat stances/sounds, `onLevelUp`, portraits, legacy tiles, tile grids, enemy skills/weaknesses/strengths and AI/escape/defeat hooks, item menu/battle hooks and clip, environment image/music/sounds/composition, and effect hooks. | Unit case collects every expected reference. | #1790 | The EDN layout printer wrote arbitrary string keys as keywords, corrupting `a b`, `x/y`, `1st`. | Keys that are not simple keyword names are written as EDN strings. | Round trip exact. **The `edn-data` library printer (`edn-oneline`) still corrupts such keys**; this is a library limitation and is recorded as such. |
| #1791 | XML decode assigned `__proto__` into an ordinary object. | Keys are defined as own data properties. | `__proto__` is preserved as data; the prototype is unchanged. |
| #1792 | XML key attributes did not escape TAB/LF, so attribute normalisation merged distinct keys. | `&#9;`, `&#10;` and `&#13;` in attributes. | `a\nb`, `a\tb` and `a b` stay distinct. |
| #1793 / #1794 | KDL insert of an object into an argument-only array appended at the end; moving scalar arguments crashed. | Mixed insert rebuilds only that array node via JiK. A scalar move reorders the argument values. | Four edit cases equal `applyOps` expectations. |
| #1795 | XML adapter emitted forbidden XML 1.0 characters (U+0000, U+FFFF, C0 controls, lone surrogates). | Uses the W3C representation's `escaped="true"` / `escaped-key="true"` with JSON escapes. | Exact round trip, and Python `xml.etree` accepts the output. |
